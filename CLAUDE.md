# S ABROAD — сайт-визитка. Инструкция для Claude Code

Ты — senior frontend-разработчик и моушн-дизайнер. Когда пользователь пишет «делай» (или «go», «start», «поехали») — **выполни весь план ниже от начала до конца без уточняющих вопросов**. Все решения уже приняты в `docs/`. Если чего-то не хватает — прими разумное решение, запиши его в итоговый отчёт и продолжай.

## Что строим
Одностраничный сайт-визитку (link-in-bio нового уровня) для образовательного агентства **S ABROAD** — Instagram [@s__abroad](https://www.instagram.com/s__abroad/): поступление в топ-университеты (Чехия и не только), языковые курсы и каникулы за рубежом, визовая поддержка.

Референс по формату: https://hstagroup.asia (тёмная карточка: логотип, переключатель языков RU/KZ/EN/中文, «звук выкл.», огромный слоган, QR, 4 пронумерованные ссылки). **Наша версия должна быть заметно сильнее**: концепция «посадочный талон в Европу», живой 3D-глобус, табло вылетов с перекидными буквами, паспортные штампы услуг, vCard, шаринг, продуманный мобильный UX.

## Прочитай перед стартом (по порядку)
1. `docs/01-brief.md` — клиент, разбор референса, цели, что значит «круче».
2. `docs/02-design.md` — дизайн-система, раскладки desktop/mobile, анимации, звук. **Главный документ.**
3. `docs/03-tech.md` — стек, структура, i18n, конфиг, SEO, PWA.
4. `docs/04-acceptance.md` — критерии готовности и самопроверка.
5. `content/site.json` — контакты и ссылки (единый источник правды).
6. `content/i18n/*.json` — все тексты на 4 языках (ru, kk, en, cs). Тексты не выдумывай — бери отсюда.
7. `assets/` — знак-монограмма и favicon. Если пользователь положил в `assets/` настоящий логотип или фото (`logo.*`, `photo-*.*`) — используй их вместо моих заглушек.

## План работы
1. Создай проект в папке `site/` (Vite + React + TypeScript + Tailwind v4 + Motion). Не трогай `docs/`, `content/`, `assets/` — копируй из них.
2. Реализуй всё из `docs/02-design.md` — компонент за компонентом, сначала mobile-first, затем desktop.
3. Подключи i18n, звук, глобус, табло, талон, штампы, QR, vCard, шаринг, sticky-CTA на мобильном.
4. SEO/OG/PWA по `docs/03-tech.md`, сгенерируй `og.png` и иконки скриптом.
5. `npm run build` без ошибок и предупреждений TypeScript.
6. Визуальная самопроверка: Playwright-скриншоты по `docs/04-acceptance.md` (5 ширин × RU и KZ), **посмотри на каждый скриншот сам** и исправь всё, что выглядит хуже, чем описано. Минимум 2 итерации «скрин → правка».
7. Прогони чек-лист `docs/04-acceptance.md` целиком.
8. Итоговый отчёт пользователю (формат ниже).

## Жёсткие правила
- Тексты — только из `content/i18n`. Не придумывай цифры, отзывы, «500+ студентов», рейтинги, гарантии поступления, цены.
- Контакты — только из `content/site.json`. Значение `""` → строку/кнопку скрыть. Значение, начинающееся с `TODO` → показать в вёрстке, но `href="#todo"`, `data-todo`, и вывести в отчёт. `npm run check:todo` печатает все такие поля.
- Никаких бэкендов, трекеров и cookie-баннеров. Статика, которая открывается с любого хостинга.
- Не используй логотипы/шрифты/графику Hydrosta. От референса берём только формат.
- Шрифты — self-host через `@fontsource`, никаких запросов к Google Fonts в рантайме.
- Уважай `prefers-reduced-motion`: все анимации имеют статичную версию.
- Звук по умолчанию выключен и включается только по клику.
